1. Solicitud y Autenticación en el API Server

Cliente ➔ kube-apiserver

El cliente (ej. kubectl apply -f pod.yaml) envía una petición POST HTTPS al kube-apiserver. Se desencadena el proceso de validación.

BASE DE DATOS DE COMPONENTES

Haz clic en un componente para inspeccionar sus estadísticas e "Habilidades Especiales".

MAPA COMPLETO DE ARQUITECTURA KUBERNETES

Coordinación desacoplada e impulsada por eventos (event-driven) entre Control Plane y Worker Nodes.

CONTROL PLANE (Plano de Control)

Psíquico / Eléctrico
kube-apiserver

Punto de entrada HTTP/REST. Autenticación, RBAC y Webhooks.

etcd

Base de datos clave-valor distribuida. Estado del clúster.

kube-scheduler

Evalúa predicates y priorities para asignar nodo al Pod.

kube-controller-manager

Garantiza que el estado deseado coincida con el actual.

WORKER NODE (Nodo Trabajador)

Lucha / Acero
kubelet

Agente en el nodo que ejecuta y monitorea los contenedores.

Container Runtime

containerd / CRI-O. Descarga imágenes y crea procesos.

kube-proxy / CNI

Configura reglas de red (IPs, iptables/eBPF) para la conectividad del Pod.

Mecanismo Event-Driven (Watch Loop)

Ningún componente fuerza llamadas directas no autorizadas. Los componentes como kube-scheduler y kubelet utilizan peticiones HTTP de larga duración (Watch) conectadas al kube-apiserver para reaccionar a cambios en tiempo real.
